# ADR 001: A governed independent creative studio

Status: implemented for a single application instance. Date: 2026-09-17.

## Decision

Use a same-origin browser UI and Python service, SQLite persistence, local private media and a narrow fal adapter. Browser assets require no build tooling and no external JavaScript/CDN. Prefer a small inspectable dependency surface over a client SDK carrying provider secrets. Original branding and preset directions avoid copying another product's assets or private workflows.

The unit of creative work is a persistent film: brief, shared visual language, ordered shots, camera/lens/light notes, selected visual take and optional selected narration. Generation is separate from selection. A completed take does not mutate the cut until the operator chooses it.

## Checkable invariants

1. Every object, job and asset lookup is constrained by authenticated tenant. Reference and export paths cannot resolve another tenant's IDs. MCP calls the same service methods as HTTP endpoints.
2. A quote binds exact validated generation input, provider endpoint, billing unit, execution mode and expiration. Approving a changed or expired reservation does not dispatch.
3. The SQLite transaction reserves budget and marks a job submitting before the sole provider POST. The idempotency key is unique per tenant; reuse with different inputs conflicts.
4. Any ambiguous response or process restart during submission quarantines the job as submission_unknown. It is never submitted again automatically. Exactly-once provider execution cannot be proved across a network partition; avoiding duplicate POSTs is the enforceable invariant.
5. Cancellation of a quoted job prevents dispatch. Cancellation of an accepted provider job is only a request; completion and billing remain possible. No speculative refund is recorded.
6. Provider result archival is retryable without regenerating. Locally stored media has a SHA-256 and provider/request provenance. Demo media is explicitly labeled and cannot silently become live execution by changing server mode.
7. Input URLs are not accepted from clients. An input image must be an owned decoded PNG, at most 4 MiB, transmitted as a data URI. Provider output URLs are restricted to exact documented CDN hosts; redirects are disabled, provider authorization is not forwarded, and downloads are bounded to 64 MiB.
8. FFmpeg never receives a shell string or remote URL. Uploads are decoded/inspected before use. Container formats are pinned during ffprobe inspection to reject disguised playlists. Exports run one at a time, with bounded subprocess durations and fixed codec/geometry settings.

## State transitions

quoted -> submitting -> queued -> running -> archiving -> completed

Additional transitions: quoted -> cancelled; submitting -> submission_unknown or failed; accepted provider jobs -> cancel_requested -> completed/failed or unresolved cancellation. Terminal states do not cause paid retry. Status polling uses canonical returned URLs, not guessed paths for nested model endpoints. Old polled jobs move behind never-polled jobs so one stalled queue cannot starve all newer work. The audit trail records state changes, not repeated identical polls.

## Cost semantics

Live schema and exact billing unit are mandatory. Image dimensions/count are fixed and whole-megapixel quantities rounded up. Video quantities include a full-second buffer for the extra endpoint frame. Voice quantities conservatively reserve at least one thousand-character billing unit. A further 25% estimate buffer is required for approval. The quote is valid for 120 seconds, but the provider does not lock its price for us.

Caps are reservation-based. They do not enforce a guaranteed provider invoice maximum. Dispatch reservations stay in the UTC day's total even when a cancellation/failure occurs. This sacrifices spend utilization to avoid accidental overspending through blind refunds. A production billing reconciliation service is a separate feature.

## Resource limits

One service worker; 24 shots and 180 seconds per export; 1 to 10 seconds per shot; 3/5/8-second generation recipes; 16 MiB uploads; 16 million image/video pixels; 300-second uploaded media duration; 4 MiB reference input; 64 MiB provider download; 512 MiB and 200 assets per tenant; 200 projects/brands/elements per kind; 500 new quotes per rolling day; 300 API requests per IP per minute. SQLite quota checks and media insertion share a transaction. Generated image alpha survives normalization.

The audit and historical job tables currently need operator retention management. The per-instance asyncio locks and crash recovery require exactly one running application worker. This is not a multi-instance durable distributed worker design.

## Security and rollout

Live mode fails startup unless HTTPS origin, server fal key and strong workspace tokens are configured. Secure/HttpOnly/SameSite sessions, exact Host/Origin validation, owner checks, strict request schemas, private media responses, no-store API caching, a restrictive CSP and escaped UI content cover the current surface. Access-token authentication is intentionally not advertised as SSO or public multi-user account management.

Before a public service launch: replace workspace bearer onboarding with reviewed OIDC, implement user/role membership and token revocation administration, move media to private signed object storage, isolate FFmpeg in a sandbox with CPU/RAM limits, introduce distributed leases, price/usage reconciliation, retention/deletion and operational metrics. Re-test real provider schema drift and exact output formats. Never promote a quality claim from simulation fixtures.

## Tradeoffs

The default local simulation makes paid-call failure cases reproducible at zero provider cost. It does not measure image quality or live queue latency. The vanilla UI avoids a build pipeline but is not a full nonlinear editor. Local media avoids leaking provider URLs through the gallery but requires disk capacity and backup. Data URI references avoid another unauthenticated media endpoint but add roughly one third to payload size; signed upload staging is the scaling replacement.

Review films normalize to 720p/24fps H.264/AAC. Images are held and selected videos loop or truncate to the authored duration. Original clip audio is deliberately replaced with the selected narration or silence. Captions use authored shot timing, not speech alignment. There are no claims of generated-camera fidelity, identity consistency, color grading accuracy or studio-quality creative output based on these integration tests.

## Acceptance

The browser must produce a playable two-shot review film from owned media. Replaying its approval must not produce a second provider POST. A different tenant must fail to read the job, reference image or exported film. A submission timeout must retain its reservation and request no automatic resubmission.
